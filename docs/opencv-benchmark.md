# OpenCV seven-segment reader and development benchmark

Date: 2026-09-25. The reader is implemented as an optional ScoreSight OCR model. The calibrated image measurements below remain development-set results, not a general accuracy claim.

## Result

| Screenshot | Expected Home | Expected Away | OpenCV Home | OpenCV Away |
|---|---|---|---|---|
| `home_1_away_0_2:58.png` | 1 | 0 | 1 | 0 |
| `home_1_away___2:54.png` | 1 | blank | 1 | blank |
| `home_2_away_2_2:52.png` | 2 | 2 | 2 | 2 |
| `home_4_away_2_2:47.png` | 4 | 2 | 4 | 2 |

**8/8 fields and 4/4 score pairs correct**, including the single blank field. Blank is an empty string; zero is `"0"`; unrecognized is JSON `null`. No smoothing or cached readings are involved.

These four images were used to develop the detector and adjust the segment sampling regions: the initial regions scored 4/8, then narrowing horizontal regions to exclude vertical strokes produced 8/8. This is therefore **development-set performance**, not evidence of general accuracy. Only digits 0, 1, 2 and 4 occur, and no image has two simultaneously illuminated digits in one score. Clock recognition is not implemented.

## Use it in ScoreSight

Choose **OpenCV Seven-Segment (2 digits, experimental)** in the OCR Model list. Draw each score box around both complete digit cells, including an unlit leading cell, and exclude nearby indicator LEDs. The reader uses the same transformed frame as OCR and exposes its color mask in Binary View. It accepts numeric fields only; clock and general-text boxes return uncertain. Its hue, saturation, brightness and occupancy thresholds are fixed in `src/seven_segment.py`; the existing Tesseract binarization/cleanup/dilation/rescale/confidence controls do not tune this reader.

Confirmed blank is `Empty`; an unknown segment pattern is `FailedFilter`. When **Skip Empty Values** is off, a confirmed blank clears the visible value, OBS, vMix, UNO, pivoted HTTP JSON/XML and text-file output. An uncertain frame leaves the last accepted output alone. Per-character smoothing is bypassed and reset for this model.

The build remains experimental: cell boundaries are split at the box midpoint and assume a nearly straight-on display. Perspective rectification, changing exposure, non-warm LED colors, reflections and LED multiplexing require more work and held-out examples.

## Reproduce

From the repository root, with the project environment installed:

```sh
.venv/bin/python tools/opencv_benchmark/benchmark.py
```

Inputs and manually verified two-slot ROIs are in `tools/opencv_benchmark/manifest.json`. Output is in `tools/opencv_benchmark/results/`: `results.json`, eight color crops and eight binary masks. `--output DIRECTORY` changes the output directory. Filenames generated by the script replace colons with underscores; the supplied input filenames themselves contain colons and must be renamed with the manifest updated before use on Windows.

## Algorithm and assumptions

Each full score ROI retains both digit slots, even when the first is unlit. It excludes the neighboring timer/indicator LEDs. The four screenshots have different board positions, so their ROIs are manually aligned separately; this prototype does not detect or track the board automatically.

The reader thresholds HSV color to select illuminated red/orange/yellow LEDs: hue at most 35 or at least 165 (OpenCV hue units), saturation at least 90, value at least 140. This suppresses the faint outlines of unlit segments in these images. It divides the score rectangle into two equal digit slots and measures the foreground fraction in seven geometric segment regions. A segment is active above a 9% occupancy threshold. The resulting bit pattern is matched exactly against the ten seven-segment digit patterns.

A cell with fewer than three foreground pixels is blank. A cell with foreground but an unknown segment pattern is rejected, without guessing its nearest digit. A lit tens position followed by a blank units position is rejected. Both blank positions produce a blank score, not zero. An illuminated zero requires its six outer segments to be present.

No machine learning, downloaded weights or external implementation code are used. This assumes a known two-slot seven-segment layout, approximately aligned images and similar LED color. It is not a general OCR replacement.

## Sensitivity checks

These are synthetic perturbations of the same four images, not independent test examples. Brightness changes multiply the BGR pixel values without gamma correction. The algorithm and thresholds remain fixed.

| Condition | Correct fields | Rejected fields |
|---|---:|---:|
| Original | 8/8 | 0 |
| 60% brightness | 1/8 | 7 |
| 80% brightness | 8/8 | 0 |
| 120% brightness | 8/8 | 0 |
| ROI shifted right 2 pixels | 6/8 | 2 |
| ROI shifted down 2 pixels | 8/8 | 0 |

The absolute brightness threshold is a clear limitation. A two-pixel horizontal alignment change can also break recognition. Rejection protects against some errors, but corrupted segments can form another valid digit pattern; exact matching cannot guarantee correctness. Extreme underexposure can also look identical to a genuinely blank display.

## Next steps before integration

- Collect held-out examples covering every digit, two-digit scores, blanks, changing exposure, reflections, viewing angles and motion. Tune only on the development subset.
- Calibrate the four corners of the display/cells and rectify perspective before sampling. Track that geometry coherently with the displayed frame and OCR coordinates.
- Estimate active versus inactive LED intensity relative to local background, with a minimum contrast gate. A fixed brightness slider alone is not sufficient for changing lighting.
- Expose separate valid, blank and uncertain states. Do not replace a rejected frame with an invented digit, and do not silently preserve a previous score as current.
- Apply short temporal confirmation to whole readings after classification; avoid character-by-character combinations of different readings. Test for LED multiplexing frames with missing segments.
- Compare the calibrated reader against OCR engines using these same complete ROIs, with preprocessing and inference timing reported separately.

The model is now integrated; these steps are needed before relying on it across scoreboard types and capture conditions.

Black formatting and Ruff checks passed for the benchmark script. The benchmark and sensitivity runs above executed with OpenCV 4.10.0. Per-call timings in JSON are diagnostic only: eight tiny crops are insufficient for a reliable speed comparison.

## Matched Tesseract comparison and warmed latency

Run `.venv/bin/python tools/opencv_benchmark/compare.py` (optionally pass `--model-directory /path/to/traineddata`). This compares the same crops and perturbations against the development-selected `7seg.traineddata`, OEM 1, PSM 8, numeric whitelist, dictionaries disabled, HSV mask H<40 or H>165, S>80, V>160, black foreground on white, 12-pixel white border, no enlargement. The adaptive classifier is cleared before each reading. These settings were selected on the same eight fields, so neither engine has independent validation here.

| Condition | OpenCV correct | Tesseract 7seg correct |
|---|---:|---:|
| Original | 8/8 | 8/8 |
| 60% brightness | 1/8 | 1/8 |
| 80% brightness | 8/8 | 7/8 |
| 120% brightness | 8/8 | 8/8 |
| ROI shifted right 2 pixels | 6/8 | 8/8 |
| ROI shifted down 2 pixels | 8/8 | 8/8 |

The Tesseract wrapper has no explicit uncertainty/rejection gate, unlike the geometry reader. At 60% brightness its LED threshold removes the foreground and it returns blank for all fields. This must not be interpreted as seven safely rejected readings. Both methods retain the genuinely blank Away field under these perturbations.

Warmed CPU latency, 10 complete warmup passes then 100 passes over eight fields (800 timed calls per engine):

| Engine | Median per field | p95 per field |
|---|---:|---:|
| OpenCV geometry | 0.183 ms | 0.252 ms |
| Tesseract 7seg | 4.181 ms | 7.486 ms |

Timing includes each engine's preprocessing, recognition and decoding; excludes imports, model initialization, file IO, crop extraction and synthetic perturbations. Tesseract OpenMP was limited to one thread. These are diagnostic timings on tiny, repeated cached inputs on this machine, not end-to-end video throughput or a universal speed ranking. Detailed readings, library version and timing metadata are saved in `tools/opencv_benchmark/results/comparison.json`. Both scripts pass Black and Ruff.
